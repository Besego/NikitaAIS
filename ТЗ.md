Техническое задание
На разработку десктопного приложения "Снабжение комплектующими"
1. Функциональные требования
1.1 Авторизация и регистрация

Регистрация новых пользователей с указанием имени, пароля и электронной почты.
Вход в систему по имени пользователя и паролю.
Разграничение прав доступа: обычные пользователи и администраторы.

1.2 Интерфейс обычного пользователя
Вкладка "Мой склад":

Отображение списка всех комплектующих пользователя (название, описание, количество, цена).
Возможность добавления новых комплектующих с указанием названия, описания, количества и цены.

Вкладка "Рейтинг":

Отображение рейтинга всех поставщиков, рассчитанного на основе количества продаж.

Вкладка "История продаж":

Отображение списка проданных товаров пользователя с деталями (дата, количество, общая стоимость).

1.3 Интерфейс администратора
Вкладка "Все поставщики":

Отображение списка всех зарегистрированных поставщиков (имя, email).

Вкладка "Все товары":

Отображение списка всех комплектующих всех поставщиков.
Возможность удаления комплектующих.

Вкладка "Все продажи":

Отображение списка всех продаж в системе.
Возможность удаления записей о продажах.

2. Нефункциональные требования

Производительность: Быстрый доступ к данным при отображении списков.
Безопасность: Хранение паролей в хэшированном виде, разграничение прав доступа.
Интерфейс: Удобный и интуитивно понятный для пользователей и администраторов.

3. Архитектура системы

Тип приложения: Десктопное приложение.
База данных: Реляционная СУБД.
Язык программирования: На усмотрение разработчика (рекомендуется Python).

4. Структура базы данных
Для реализации функционала предлагается следующая структура таблиц:
4.1 Таблица "Пользователи" (Users)

user_id (PK): Уникальный идентификатор пользователя (целочисленный).
username: Имя пользователя (строка).
password: Хэшированный пароль (строка).
role: Роль пользователя ('user' или 'admin') (строка).
email: Электронная почта (строка).

4.2 Таблица "Комплектующие" (Components)

component_id (PK): Уникальный идентификатор комплектующего (целочисленный).
user_id (FK): Идентификатор пользователя-владельца (целочисленный, ссылка на Users).
name: Название комплектующего (строка).
description: Описание (строка).
quantity: Количество на складе (целочисленный).
price: Цена за единицу (десятичное число).

4.3 Таблица "Продажи" (Sales)

sale_id (PK): Уникальный идентификатор продажи (целочисленный).
component_id (FK): Идентификатор проданного комплектующего (целочисленный, ссылка на Components).
user_id (FK): Идентификатор пользователя, совершившего продажу (целочисленный, ссылка на Users).
quantity: Количество проданных единиц (целочисленный).
sale_date: Дата продажи (дата).
total_price: Общая стоимость продажи (десятичное число).

Окно авторизации: Поля для ввода имени пользователя и пароля, кнопки "Войти" и "Зарегистрироваться".
